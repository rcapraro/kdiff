## Why

Before `1.0.0` a minor version may break; after it, every one of the decisions below costs a major
version. Each is small on its own. Together they are the difference between a public surface that was
shaped on purpose and one that kept whatever the first implementation happened to expose:

```
  today                                        the question it leaves open
  -------------------------------------------  ------------------------------------------------
  Patched<T> and PatchResult<T>                two names for "a value and its failures", with a
                                               conversion between them in patchNested
  data class Diff(val changes)                 copy(changes = …) and component1() are public API;
                                               Diff(changes=[ValueChanged(path=…)]) is its toString
  interface Differ<T> { fun diff(…) }          a one-method interface that cannot be a lambda
  Segment.Key("key", k) for a map entry        a literal a hand-written patcher must know
  Diff carries no T                            at<Order>(…) has to be told its type; decided in
                                               0.4.0 but recorded nowhere a 1.0 reader will look
```

None of these is a defect. All of them are things a reader of the API in two years will ask about, and
the honest answer should be "we decided" rather than "it was like that". The ABI dump makes every one
of them visible, which is what it is for; this change is the review it invites.

## What Changes

**BREAKING — `Patched<T>` is removed; the patch helpers return `PatchResult<T>`.** `patchValue`,
`patchNested`, `patchNestedNullable`, `patchKeyedList`, `patchPositionalList`, `patchSet`, `patchMap`,
`unpatchable` and `notConstructorProperty` all return the type a `Patcher.apply` returns. The two types
had identical shape and `patchNested` existed partly to convert one into the other. A hand-written
patcher that named `Patched` renames it; one that only read `.value` and `.failures`, which is every
example in the docs, compiles unchanged. Generated code is regenerated by the same processor and reads
the same two members.

**BREAKING — `Diff` is no longer a data class.** It keeps its constructor, its equality over its
changes, and every member it has. It loses `copy` and `component1`, which nobody asked for and which
would make adding anything to `Diff` a breaking change forever. Its `toString()` becomes the same text
`render()` produces, so a diff printed in a log or an assertion failure reads as a diff. Every other
data class in the API — the five `Change` variants, the three `Segment` variants, `PatchResult`,
`PatchFailure`, `DiffNode`, `TrackedField` — stays a data class, by a written criterion: its fields are
its whole meaning, destructuring is a use, and the shape will not grow.

**`Differ` and `Patcher` become `fun interface`s.** A one-off differ can be a lambda:
`Differ<Money> { a, b -> … }`. Binary-compatible, source-compatible, and the ABI dump does not move.

**The name a map entry's key segment carries is a declared constant.** `Segment.Key.MAP_ENTRY` replaces
the literal `"key"` in the runtime, so a hand-written differ or patcher building a map path can name it
and a reader of `amounts[key=eur]` can find where `key` comes from.

**The decisions not taken are written down.** A new `docs/api-stability.md` states what `1.0.0` will
promise — the recorded public API, the two closed vocabularies, which types are data classes, the JVM
target, what generated code guarantees and what it does not — and records the questions answered "no":
a typed `Diff<T>`, `TypeChanged` carrying classes rather than names, a common exception supertype. Each
with the reason, so the next person to ask finds the answer.

**Not in scope**

- Typed handlers — `onValue(Order::status) { before, after -> }` in routing and a typed per-property
  listener in the tracker builder. Additive, valuable, and a separate change; bundling an addition into
  a change whose purpose is to settle breaks muddles the changelog entry for both.
- `Diff<T>`. Considered and declined; the reasoning goes in `api-stability.md`, not into code.
- Renaming anything for taste. Every rename here removes a duplicate or a literal.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `diff-generation`:
  - MODIFIED *A diff result reports an ordered list of changes* — a `Diff` offers no copy and no
    destructuring; its text form is its rendering.
  - MODIFIED *A diff can be rendered as text* — the text form is reachable as the diff's own string
    conversion.
  - MODIFIED *A change identifies where it was found* — the key-property name a map entry segment
    carries is a declared constant.
  - ADDED *A differ or a patcher can be written as a single expression* — the functional-interface
    shape.
- `diff-application`:
  - ADDED *The helpers a hand-written patcher composes return the patcher's own result type* — one
    result type, so composition needs no conversion.

`change-tracking` and `build-quality-gates` need no delta. The ABI dump moves exactly where the proposal
says it does, and the gate that guards it is unchanged.

## Impact

- **Modules**: `kdiff-runtime` (all of it), `kdiff-processor` (nothing — it emits `.value` and
  `.failures`, which both types had), `kdiff-sample` and `kdiff-tutorial` (recompile; the sample's
  hand-written `MoneyDiffer` reads `.value` and compiles unchanged), docs.
- **Public runtime API**: `Patched` and its members leave the dump; `Diff.copy`, `Diff.copy$default`
  and `Diff.component1` leave it; `Segment.Key.Companion` and `MAP_ENTRY` enter it. `updateKotlinAbi`
  runs once and its diff is exactly that list, which is the review surface for this change.
- **Generated API surface**: unchanged. The generated object, its three interfaces and its two
  functions are as they were; regenerating picks up the new helper return type without any textual
  difference in the emitted file.
- **Annotation semantics**: unchanged.
- **Breaking, in two places, both source-level and both mechanical**: a `Patched` rename, and a
  `Diff.copy` or destructuring call that no documented usage makes. The `CHANGELOG.md` entry carries
  both migrations in one line each.
- **Docs**: `docs/api-stability.md` is new and linked from the README's *Status* and from
  `docs/README.md`; `patching.md` shows `PatchResult` where it showed `Patched`; `hand-written.md`
  gains the lambda form and the `MAP_ENTRY` constant; `diffing.md`'s *Viewing a diff* notes that
  `toString` renders.
- **Dependencies**: none added. No version bumped.
